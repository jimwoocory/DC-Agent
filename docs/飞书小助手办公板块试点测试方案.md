# 飞书小助手办公板块试点测试方案

## 1. 测试结论口径

本方案验证两个问题：

1. `查资料/分析`、`处理文件`和其中的翻译能力是否按当前规则可靠运行。
2. 这些能力是否真实节省公司员工时间，并产生可直接使用的工作结果。

技术测试通过不等于公司需求成立。业务价值必须通过真实员工、真实材料和重复使用数据验证。

## 2. 当前产品基线

| 能力 | 当前规则 | 本轮重点验证 |
|---|---|---|
| 查资料/分析 | 材料 → 研究问题 → 模式、深度、来源、内容结构和交付方式；保存一次后直接执行 | 证据来源是否可追溯；事实、推断、建议和未知项是否分开；深度选项是否真实影响执行 |
| 处理文件 | 必须先提供上传文件、飞书云文档或明确的 HTTP(S) 文件 URL；再选择总结、提取、改写、转换、对比、整理或翻译 | 是否读取完整材料；两个版本对比是否要求至少两份材料；交付文件是否真实可打开 |
| 翻译 | 一次任务处理一份主材料；目标语言必填；支持忠实/专业、术语、翻译记忆和双向互译 | DOCX/XLSX 结构是否保留；公式、数字和样式是否不被误改；异常文件是否明确失败 |
| 交付 | 研究可交付结果卡、DOCX、XLSX、PDF、飞书文档；文件处理可交付 DOCX、XLSX、PDF、TXT、飞书文档 | 不允许只改提示词却声称已生成文件；交付物必须能打开且内容对应任务 |
| 材料限制 | 最多 10 项、单项 80 MB、总计 200 MB；工作区能力令牌默认 30 分钟有效 | 超限、过期、非法 URL 和不支持格式必须在模型调用前被拒绝 |

## 3. 试点范围

### 3.1 本轮自动执行

- 菜单、卡片、H5 三步流程和保存执行边界。
- 研究、文件处理、对比、翻译和真实交付物回归测试。
- 上传数量、大小、令牌过期和输入校验。
- NAS 线上入口可达性和过期工作区恢复页。
- 当前使用量、延迟和错误率基线。
- 前端宣称格式与后端真实解析能力的一致性检查。

### 3.2 两周人工业务试点

- 参与人：市场、筹备/采购、行政等 10–15 人。
- 周期：连续 2 周。
- 每项任务使用真实但已授权的公司材料。
- 不让通用文件处理代替财务、HR、审批、报价入库等专用事务流程。

## 5. 两周业务试点用例

| ID | 真实任务 | 试点材料 | 合格标准 | 优先级 |
|---|---|---|---|---|
| B01 | 总结一份方案或会议材料 | 5–30 页 DOCX/PDF | 关键结论无遗漏，员工修改不超过 10 分钟 | 高 |
| B02 | 提取合同、报价或供应商资料字段 | 两类真实文档 | 字段准确率 ≥95%，遗漏项明确列出 | 高 |
| B03 | 对比两个版本 | 两版合同、方案或报价 | 变更点、影响和风险能定位到来源 | 高 |
| B04 | 形成决策研究简报 | 业务问题 + 内部材料 + 公共来源 | 引用可核验，结论能区分事实与建议 | 中高 |
| B05 | 翻译一份真实业务文档 | DOCX 或 XLSX | 术语正确，结构可用，公式和数字零误改 | 条件性 |

每个任务结束后记录：原人工耗时、系统总耗时、人工修订耗时、能否直接使用、是否愿意再次使用、问题类型和材料敏感级别。

## 6. 业务通过门槛

两周结束后同时满足以下条件，才建议扩大范围：

- 完成真实任务不少于 20 个。
- 技术交付成功率 ≥90%。
- 用户判断“可直接使用或少量修改可用”的比例 ≥70%。
- 试点员工重复使用率 ≥30%。
- 自动任务端到端中位耗时 <60 秒；长文档任务单独统计。
- 机密材料误传、越权访问和留存违规为 0。
- 至少 3 类高优先级任务各有 3 次以上成功样本，避免被单个演示案例误导。

若业务门槛未达到，优先保留“总结 / 提取 / 对比”，暂停扩大泛化的“改写 / 转换 / 整理”，研究入口收窄为“决策研究”，翻译继续作为高级能力灰度。

## 7. 上线阻断项

以下任一项成立时，不进入全员发布：

- 前端接受后端不能完整解析的文件格式。
- 长文件或多文件只读取片段，但界面未明确标注“部分读取”。
- `研究深度`或`模型档位`只是提示词文本，没有真实执行差异。
- 公司内部/机密材料没有数据分级、部门权限和外部模型规则。
- 上传材料、NAS 收件箱和输出文件没有明确保留期与自动删除机制。
- 无法统计任务从打开到完成的漏斗，也无法区分失败、返工和真实可用。
- 当前实现未纳入可复现的版本管理和部署验证。

## 8. 缺陷分级与处理

| 等级 | 定义 | 处理 |
|---|---|---|
| P0 | 数据泄露、越权、错误覆盖原文件、财务数字或公式被静默修改 | 立即停止试点 |
| P1 | 声称读取完整文件但实际只读片段、交付文件损坏、研究引用不可核验 | 修复并全量回归后继续 |
| P2 | 格式偏差、耗时过长、提示不清但有恢复路径 | 记录并在扩面前解决 |
| P3 | 文案、样式和非阻断体验问题 | 纳入迭代 |

### 9.1 实测发现

1. 上传入口允许 32 种后缀，但文档接入解析配置只有 9 种。当前共有 24 种“可以上传但不能由文档接入链路解析”的后缀，包括图片、音视频、压缩包、旧版 DOC/PPT、CSV 和 RTF 等。前端不能继续把这些格式表现为通用办公文件能力。
2. 当前 4 份 AstrBot 配置的 `file_extract.enable` 均为 `false`。文档接入插件会向普通 LLM 路径注入最多 12,000 字符的合并片段，因此长文件和多文件任务不能承诺“完整读取”；界面目前也没有清楚标注只读片段。
3. `research_depth`在普通研究路径中只进入任务提示；通用`model_choice`没有映射到普通研究/文件任务的真实模型或预算。翻译路径会真实使用`model_choice`，但不能据此证明其他办公任务的档位有效。
4. 在办公相关实现中未发现材料“公开/内部/机密”分级、部门/角色访问门槛、外部模型规则、上传附件/NAS 收件箱/输出文件的自动删除周期。
5. 现有审计能统计全局模型调用，但不能形成办公任务的“打开 → 上传 → 提交 → 完成/失败 → 返工 → 用户评价”漏斗。近 30 天持久化消息中未检出结构化办公任务标记，103 条 harness 任务中也未检出研究/文件/翻译任务；本地办公输出目录为 0 个文件。当前没有足够证据证明真实采用率。
6. 办公工作台、路由和翻译的关键实现文件在当前工作区仍是未跟踪状态。自动测试能够证明本机代码行为，但不能单独证明 NAS 正在运行完全相同的版本。

## 10. 当前决策

- 技术结论：**有条件通过**。核心交互、校验、交付和翻译回归均通过，但 A11–A14 阻止全员发布。
- 业务结论：**需求方向成立，真实采用证据不足**。先验证总结、提取、对比和决策研究；翻译作为条件性高级能力。
- 建议保留：总结、结构化提取、双版本对比、可追溯的决策研究。
- 建议收窄：`查资料/分析`改为`决策研究`；`处理文件`优先展示`总结 / 提取 / 对比`；翻译放入高级能力。
- 建议暂停扩面：泛化改写、转换和整理；在格式、完整读取、权限留存和观测闭环修复前不全员开放。
- 下一步：先处理 A11–A14，再由试点负责人确定 10–15 人名单和两周起止日期，执行 B01–B05。
